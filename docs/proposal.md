## 2. 需求分析

### 2.1 目标用户

- **家长 / 幼教老师**：想给孩子快速定制一本"主角就是自家孩子"的绘本或睡前有声故事；
- **儿童内容创作者**：需要批量产出图文、音频、视频素材的初稿；
- **学生 / 开发者**：想直观看到多模态 Agent 的规划、工具调用与干预重算过程。

### 2.2 核心功能列表（含优先级）

| # | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| F1 | 创意→多模态产品 | P0 | 输入创意一句话 + 主角设定，Agent 规划并执行 写作→配图→配音→剪辑→排版，产出 4 种模态产物 |
| F2 | 创作中途干预 | P0 | 对话框输入"把主角改成女孩""换个场景"，Agent 解析变更、只重跑受影响的下游工具 |
| F3 | 全程可观测 | P0 | 每步工具名/入参/耗时/产物实时展示，创作日志可导出（Markdown + JSON trace） |
| F4 | API 可靠性 | P0 | LLM/文生图调用带重试+指数退避、本地响应缓存、无密钥时自动降级为离线模板生成 |
| F5 | 成本计量 | P1 | 按 token/张数估算每次创作成本，UI 显示"本次花了多少钱" |
| F6 | 素材检索推荐 | P1 | 创意先经 RAG 素材库检索，把匹配的故事模板/配图风格/音效注入写作 Prompt |
| F7 | 多角色有声书 | P1 | 按角色分配音色，按情绪标注调整语速音调，输出带时间轴的 MP3 |
| F8 | 字幕短视频 | P2 | 图片+音频按时间轴自动剪辑，字幕逐句对齐并烧录 |
| F9 | Web 界面 | P0 | 零依赖本地 Web UI（标准库 http.server），双击即可演示 |

### 2.3 用户故事（≥2）

**US-1**：作为一名家长，我想输入"太空冒险，主角是我 6 岁的女儿朵朵"，几分钟内拿到一本朵朵当主角的绘本和一段睡前故事音频；当我觉得主角名字不合适时，我直接说"把主角改成朵拉"，系统只重做受影响的产物，前面生成的图不浪费。

**US-2**：作为一名儿童内容创作者，我想批量输入 3 个创意，让 Agent 在夜间自动产出图文音视频初稿，并收到一份包含每步耗时与成本估算的创作日志，方便我挑出值得精修的方案。

### 2.4 非功能性需求

| 类别 | 要求 |
| --- | --- |
| 可靠性 | 任一外部 API 失败不导致整体崩溃：重试→降级→报告，产物缺失有明确标记 |
| 可复现 | 固定随机 seed；同一输入在离线模式下产物逐字节一致，方便测试 |
| 性能 | 离线模式端到端 ≤ 3 分钟；在线模式主要瓶颈为 API，允许异步执行 |
| 成本 | 单案例在线成本 ≤ ¥2；缓存命中后重复创作成本 ≈ 0 |
| 安全 | API Key 只存 `.env`，`.gitignore` 排除；故事内容经过敏感词过滤后输出 |
| 兼容 | Windows / macOS / Linux，Python ≥ 3.10，可选依赖缺失时自动降级 |

## 3. 技术架构设计

### 3.1 系统架构图

```
┌─────────────────────────── Web UI (web/index.html) ───────────────────────────┐
│   创意输入 │ 进度面板(每步状态/耗时/产物) │ 干预对话框 │ 成本仪表 │ 产物预览     │
└───────────────▲──────────────────────────────────────────┬────────────────────┘
                │ JSON / SSE                               │ HTTP
┌───────────────┴──────────────────────────────────────────▼────────────────────┐
│                        server.py（标准库 http.server，零依赖）                 │
├───────────────────────────────────────────────────────────────────────────────┤
│  agent.py  ── Agent 循环：observe → plan → act → observe → replan              │
│     │   规划器可插拔：LLMPlanner（在线拆步骤）/ RulePlanner（离线固定DAG）       │
│     │   干预：变更解析 → 依赖图 affected 计算 → 下游重跑                        │
│     ▼                                                                         │
│  tools.py（工具注册表：name/schema/fn/produces）                                │
│   ├── search_materials ──► retrieval.py（TF-IDF 字符n-gram + 素材库）          │
│   ├── write_story ──────► llm.py（重试/缓存/JSON修复） + templates.py(降级)    │
│   ├── illustrate ───────► illustration.py（在线文生图 / 本地PIL插画，seed固定）│
│   ├── voice ────────────► tts.py（edge-tts 多音色/情绪参数 → timeline.json）   │
│   ├── compose_video ────► video.py（ffmpeg：图片+音频+字幕按时间轴合成）        │
│   └── build_book ───────► book.py（PIL 排版 → PDF）                            │
├───────────────────────────────────────────────────────────────────────────────┤
│  schema.py（Story/Scene/Character 校验）   cost.py（token/张/句 计量）          │
└───────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 技术栈清单（含版本）

| 层 | 技术 | 版本 | 用途 |
| --- | --- | --- | --- |
| 语言 | Python | ≥ 3.10（本机 3.13） | 全部后端 |
| LLM 接口 | openai SDK（OpenAI 兼容） | ≥ 1.0 | DeepSeek/通义等，可选 |
| 文生图 | dashscope SDK 或 REST | 最新 | 通义万相，可选 |
| TTS | edge-tts | 7.x | 多角色语音，需联网 |
| 图像处理 | Pillow | ≥ 10 | 本地插画、封面、PDF 排版 |
| 视频 | imageio-ffmpeg（自带 ffmpeg 静态二进制） | ≥ 9 | 合成短片，免安装 ffmpeg |
| Web | 标准库 http.server | 内置 | 本地演示服务，零依赖 |
| 测试 | unittest | 内置 | 单元测试 |
| 配置 | python-dotenv 语义的自研 30 行解析 | - | .env 加载，避免强依赖 |

设计原则：**核心功能零付费依赖可跑**（mock LLM + 本地插画 + 静音降级），联网与密钥是"增强项"而非"门槛"。

### 3.3 多模态数据流

```
创意文本
  │ search_materials（检索模板/风格/音效 → 注入 Prompt）
  ▼
write_story ──► story.json（title/characters/scenes[mood,visual_prompt]/moral）
  │                        │
  │                        ├─► illustrate ──► sceneNN.png ×N（固定seed+特征卡保持一致）
  │                        │
  │                        └─► voice ──► story.mp3 + timeline.json（每句起止时间/音色）
  │                                            │
  ├────────────────────────────────────────────┴─► compose_video ──► story.mp4（图+音+字幕）
  └────────────────────────────────────────────────► build_book ───► story.pdf（封面+图文页+寓意页）
```

关键点：**单一数据源**（story.json + timeline.json）驱动全部模态，任何干预只触发受影响分支。

### 3.4 关键技术难点与解决方案（≥1）

**难点 1：干预后"重算最小集"的确定。** 用户改主角名字时，重画 8 张图既慢又花钱，但不重配音频又会出现"图上是朵拉、耳朵里是朵朵"的模态间不一致。

解决方案：把工具间依赖显式建模为依赖图 `DEPENDS = {write_story:[request], illustrate:[story], voice:[story], compose_video:[story,voice], build_book:[story,illustrate]}`；干预解析出变更字段后，按"字段→受影响工具"映射计算最小重算集：改主角名 = 确定性全文替换（不重写故事）+ 重跑 voice/compose_video/build_book，illustrate 产物直接复用。该逻辑有单元测试覆盖（第 13 周交付）。

**难点 2：无密钥/断网环境的可演示性。** 课堂演示最怕现场 API 故障。

解决方案：三级降级链——LLM：在线调用 →（失败）→ 缓存回放 →（无缓存）→ 模板创作器；文生图：在线 → 本地程序化插画（PIL，固定 seed 保证角色一致）；TTS：edge-tts → 静音时间轴（视频仍有画面与字幕）。降级事件写入 trace，答辩时可作为"工程可靠性"的现场证据。

**难点 3：字幕与语音的逐句对齐。** edge-tts 不返回句级时间戳。

解决方案：逐句单独合成，用返回的音频时长建立每句起止时间轴；视频按时间轴切帧，字幕用 PIL 烧进对应帧，避免 ffmpeg drawtext 的中文转义问题。

## 4. 大模型工程方案

| 项 | 方案 |
| --- | --- |
| Prompt 管理 | `prompts.py` 集中管理，每条 Prompt 带版本号与用例名（v3-schema-selfcheck）；素材检索结果以 `<context>` 块注入；输出一律要求 JSON 并经 schema 校验 |
| API 调用设计 | 重试：最多 3 次，指数退避（2^n + 0.5n，上限 8s）；缓存：`sha256(model\|temperature\|system\|user)` 为键落盘 `.cache/`，重复创作零成本；降级：见难点 2；JSON 修复：剥围栏→括号配平→尾逗号清理→追加"只输出JSON"重试一次 |
| 成本控制 | 按 token 估算成本（¥/千token 可配置）；缓存优先；图片懒生成（干预未触及的场景不重画）；UI 实时显示本次成本 |
| 评估方法 | 结构：schema 校验通过率；文本：场景数/字数达标率 + 3 组固定创意的人工 5 分制评分（第 13 周测试报告）；检索：R@5 与 Top1 命中率（沿用第 6 周评估集） |
